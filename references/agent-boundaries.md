# Agent Boundaries

## 职责分界

人负责目标、价值取舍、架构边界、风险上限、外部授权、验收标准和最终责任。Agent 可以搜索、实现、重构授权范围、运行验证、整理证据和执行重复操作。

高吞吐能力不构成扩大权限的理由。

## 范围合同

向 Agent 下发任务时至少包含：

```text
目标：
允许修改：
禁止修改：
必须保持：
可用权限：
回滚要求：
验收证据：
停止条件：遇到边界外依赖、不可逆风险或证据不足时停止并报告。
```

“顺手修一下”“全面整理”“看见问题都处理”不是可验证范围。把相邻问题记录为后续项，除非它阻止当前目标或用户明确重订合同。

## 权限阶梯

1. **观察**：读取代码、日志、状态、配置和版本。
2. **模拟**：dry-run、静态分析、测试环境、Shadow Mode。
3. **局部写入**：单模块、隔离工作区、可撤销配置或小批数据。
4. **受限控制**：canary、限幅、速率限制、明确停止条件。
5. **扩大执行**：只有前一级证据满足门槛后才进入。

每一级只获得当前步骤需要的权限。授权执行某项任务，不自动授权清理环境、修改生产、访问秘密或扩大外部副作用。

## 脏工作树与用户改动

写入前先识别未提交、未跟踪和重叠文件。可接受的保护方式包括：

- 在不改变原目录的隔离工作区实施；
- 建立能完整恢复原改动的补丁、快照或等价备份，并验证可读；
- 若宿主工作流提供安全的变更隔离，使用它并保留原改动归属。

仅承诺“小心合并”“不会覆盖”不构成恢复机制。若任务约束禁止所有隔离和可恢复基线，而改动会与未知工作重叠，停止写入并明确说明为什么无法安全继续。

不要擅自暂存、丢弃、覆盖、移动或重写用户改动。

## 高风险写操作

按顺序执行：

1. **检查**：解析精确目标、当前状态、影响面和权限。
2. **预览**：dry-run、diff、待修改记录计数或 canary 计划。
3. **执行**：最小批次、可中止、保留审计记录。
4. **验证**：检查目标结果、副作用和恢复能力。

执行前验证回滚，不要把“有备份”当作“能恢复”。不可逆、目标不明确或回滚未验证时停止。

## 边界变化

执行中发现必须改协议、公共接口、数据语义、兼容承诺、生产配置或无关模块时，这不是普通实现细节。暂停当前任务，更新目标、影响面、授权和验证合同后再继续。
