# Anti-Patterns

| 反模式 | 危险信号 | 修正 |
|---|---|---|
| 模糊目标直接执行 | “现代化”“彻底优化”“做得更优雅” | 改写为用户结果、非目标和证据 |
| Agent 自行扩域 | “顺手整理”“既然改了就统一” | 保持任务合同；相邻问题另记 |
| 只靠谨慎保护脏改动 | “我会精确合并，不会覆盖” | 写入前建立隔离或可恢复基线 |
| 无回退的高风险写入 | “样例跑过了”“备份应该能用” | dry-run、恢复演练、canary、停止条件 |
| 完成声明替代证据 | “看起来正确”“历史上都通过” | 报告当前证据；缺失即 `Unverified` |
| 回滚窗口耗尽 | 一直等待测试，没有最晚决策点 | 从回滚耗时倒推 go/no-go |
| 未来需求驱动框架 | 为未确认场景建立大量扩展点 | 只抽象已观察的重复和稳定边界 |
| 错误抽象 | 大量开关、类型判断和例外 | 重新划分边界，允许清晰重复 |
| 紧急恢复绑架构重构 | 为一次事故直接上大隔离方案 | 先最小可逆降级，再评估长期改造 |
| 静默吞错 | 核心继续运行但没有错误状态或日志 | 局部化故障并保留可观察失败 |
| workaround 冒充根因修复 | “稳定两周，可以关闭问题” | 区分 `Mitigated` 与 `Fixed`，设置退出条件 |
| 无观测的自动化 | 直接让策略接管生产 | baseline → observability → shadow → limited control |
| 盲目进入陌生栈 | 让 Agent 重写最陌生层 | 先定位系统层、依赖、失败影响和最小实验 |
| 代码完成即工程完成 | 忽略构建、产物、安装、升级和真实环境 | 以用户闭环定义完成证据 |
| 补丁堆叠 | 重试、重启、定时任务逐层掩盖症状 | 保留有界缓解，同时建立根因复现和回归 |

## 自我合理化警报

- “这次时间紧，之后再补恢复点。”
- “用户授权很宽，所以范围不需要再定义。”
- “Agent 已经说完成，测试只是确认一下。”
- “未来肯定会需要这个框架。”
- “只要指标变好，根因并不重要。”
- “有 fallback，但从未演练也没关系。”

出现这些表述时，回到任务合同，重新检查范围、证据、复杂度和失败恢复。不要自动升级为最重流程；选择与真实影响面相称的最小控制。
