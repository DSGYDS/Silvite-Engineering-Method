# Project-Driven Learning

## 项目是知识缺口探测器

真实任务持续产生比课程目录更具体的问题：哪个状态不稳定、哪个边界泄漏、哪个依赖不可替换、哪个证据缺失。利用这些卡点安排学习，可以更快建立与系统结构对应的知识。

```text
真实目标
  → 最小闭环
  → 暴露卡点
  → 定位系统层和知识缺口
  → 补理论或做小实验
  → 回项目验证
  → 记录新模式与边界
```

## Agent 的脚手架角色

Agent 可以：

- 解释错误和领域词汇；
- 找到文档入口和最小实验；
- 映射组件、接口与依赖；
- 生成隔离的样板或测试；
- 根据日志提出可证伪假设。

Agent 不应：

- 在未知层直接大规模重写；
- 用生成速度替代系统理解；
- 把一次运行成功当作掌握领域；
- 在没有恢复路径时用真实资产做探索实验。

## 什么时候必须补理论

当以下缺口阻止正确判断时暂停实现并下钻：

- 无法解释关键状态、并发或时序；
- 无法判断内存、资源或性能上限；
- 无法区分多个层级的失败；
- 无法设计诚实的测试或反例；
- 修改可能触及安全、数据完整性或不可逆设备状态。

学习深度由当前决策所需证据决定；关键地基最终必须补齐，但不要求在看到完整问题前学完整个领域。

## 保留工程认知

记录可复用的“现象 → 假设 → 实验 → 证据 → 决策 → 反例”，而不仅是最后答案。一次项目特例只有在多个场景中重复出现，并能删除项目背景后仍成立，才升级为通用规则。
