# Verification and Completion

## 证据优先

Agent 的完成声明是待验证的报告，不是工程事实。证据应独立于实现叙述，并与风险和目标环境相匹配。

## 证据矩阵

| 变化类型 | 常见必要证据 |
|---|---|
| 局部逻辑 | 针对性测试先失败后通过；相关回归通过 |
| API / Backend | 契约、错误路径、数据副作用、集成测试、运行日志 |
| UI / Client | 构建、关键交互、状态变化、目标设备或等价环境 |
| Library | 公共接口兼容、消费者测试、版本与产物检查 |
| Cross-platform | 各端验证、协议/版本兼容、断连与恢复、跨边界日志 |
| Embedded / Device | 模拟或隔离设备、时序/资源证据、恢复路径、实机验证 |
| Data migration | dry-run、影响计数、备份恢复演练、canary、前后一致性 |
| Automation | Known-Good 对照、Shadow 数据、限制条件、fallback 演练 |

不是每项修改都需要表中全部证据；必须覆盖最可能失败且用户真正依赖的路径。

## 完成状态

- **Completed**：请求结果与必要回归已有新鲜证据。
- **Mitigated**：影响已被限制或服务已恢复，但根因或长期方案尚未验证。
- **Unverified**：实现存在，但关键测试、构建、产物或目标环境证据缺失。
- **Blocked**：缺少权限、环境、信息或安全恢复路径，无法继续。

报告应列出：改了什么、没有改什么、运行了什么、结果是什么、哪些未运行、残余风险和回退位置。

## 回滚窗口倒推

回滚权限或时间有限时：

1. 估算回滚执行和验证所需时间。
2. 从窗口结束点倒推出最晚 go/no-go。
3. 在该时点之前必须取得继续运行的证据；否则回退。
4. 不要持续等待测试直到失去实际回退能力。

历史通过率、局部测试或“看起来正确”不能替代当前结果。

## 独立验证

实现者或 Agent 已运行测试后，验收仍应重新读取完整输出、退出码、失败数和产物。复杂或高风险系统优先让不同执行上下文、独立测试或目标环境验证关键结论。

如果无法获得必要证据，准确写 `Unverified`。这不是失败的措辞，而是工程状态。
